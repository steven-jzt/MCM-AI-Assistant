# Subagent 调度协议

## 默认策略：只派发固定质量门

默认模式只派发 5 个固定质量门（M1/P1/P2/W1/W2），其余协作默认关闭。

## 必守原则

- 门控 Subagent 默认只读，不修改任何文件。
- 每个门必须返回固定格式回执：范围 / 输入快照 / 状态(PASS|FAIL|BLOCKED) / 证据 / 发现 / 返工建议。
- Subagent 的派发者（教练）负责解读回执并决定返工策略，不将决策权委托给 Subagent。
- 文献检索使用独立工具，不按搜索引擎拆分 Subagent 任务。

## 固定质量门

| 门 | 时机 | 关注点 | 解除条件 |
|----|------|--------|---------|
| M1 | 建模手交付前 | 结论-模型匹配、证据链完整性、模型数量、**数据探索完成度** | 每个子问题≤2 独立模型，术语一致，结论可检验，数据已做全貌探索并记录处理决策 |
| P1 | 编程手全量计算前 | 最小可运行结果、**数据筛选合理性** | 输入输出链路跑通，结果可复现，数据筛选有领域理由 |
| P2 | 编程手交付前 | 代码可复现性、图的质量与数量、表格完整性、复现清单、**结果可靠性与稳健性分析** | figure_audit 通过，≥9 张图（PNG+SVG），复现清单完整，结果含误差评估或交叉验证，关键参数敏感性扫描完成 |
| W1 | 论文手长正文前 | 证据大纲完整性 | 每个结论都有可追溯证据 |
| W2 | 论文手交付前 | 全文一致性、**AI 使用台账完整性** | 公式/图表/文献/格式全部校验通过，AI 使用台账三阶段均已填写 |

## 派发输入格式

主流程向每个门派发以下信息：

```
任务说明：[本门要核验什么]
输入快照：[文件清单 + SHA-256 校验和]
相关文档路径：[角色文档、上阶段交付物、数据文件等]
关注重点：[本门特别在意的 2-3 个风险点]
```

## 回执格式

每个门必须返回：

```
范围：[本门关注的文件/结果范围]
输入快照：[文件清单 + 校验和]
状态：PASS | FAIL | BLOCKED
证据：[支撑判断的具体证据，引用文件路径和行号]
发现：[P0/P1/P2 分级的问题清单]
返工建议：[若 FAIL/BLOCKED，给出具体返工指引]
```

### 状态含义

| 状态 | 含义 | 后续动作 |
|------|------|---------|
| PASS | 全部核验项通过 | 进入下一阶段 |
| FAIL | 有可修复的问题 | 按返工建议修改后重新派发本门 |
| BLOCKED | 有前置条件未满足 | 先补前置条件，再重新派发本门 |

## 反馈回路

- **建模手产出被 M1 驳回**：先改模型设计再补证据，而非先补证据再维持原模型。若缺少数据探索，先补数据质量分析。
- **编程手产出被 P1 驳回**：先修可复现性再补图，而非先补图再修代码。若缺少数据筛选理由，先补数据质量分析。
- **编程手产出被 P2 驳回**：先修代码与数据一致性，再调图。若缺少稳健性分析，先补敏感性扫描或交叉验证。
- **论文手产出被 W1 驳回**：先补证据链缺口，再写长正文。
- **论文手产出被 W2 驳回**：先修公式/图表/文献硬错误，再调格式。若 AI 使用台账不完整，先补填。

## 用户显式启用才可用的协作（默认关闭）

以下协作型 Subagent 默认不派发，仅当用户明确启用时才启动：

- **规则核验**：用独立规则清单复核论文是否违反官方要求
- **附件清点**：核验数据附件是否完整、格式是否正确
- **文献与模型族调研**：检索相关文献，验证模型选择的合理性
- **隔离算法原型**：在隔离环境中验证新算法思路的可行性
- **独立实验批次**：用不同随机种子跑独立实验验证稳定性
- **Python/MATLAB 对照实现**：两语言独立实现同一模型并交叉验证
- **术语核验**：检查全文中术语、符号是否一致

## 绝不委托

以下决策权始终保留在主流程（教练），不可派发给 Subagent：

- **官方规则裁决**：CUMCM/MCM-ICM 官方规则的最终解释
- **交付物结构定案**：论文大纲、模型选择、格式参数的最终决定
- **证据链最终判定**：某个证据是否足以支撑某个结论
