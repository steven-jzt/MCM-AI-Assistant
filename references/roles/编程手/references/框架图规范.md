# 框架图规范（非数据型图示）

> 数学建模论文的图分两类，**二者缺一不可**：
> - **数据图**（讲「效果」）：折线、柱状、热力图、散点等 → 走 `utils/visual.py`
> - **框架图**（讲「逻辑」）：技术路线图、流程图、模型结构图等 → 走 `utils/diagram.py`
>
> 本文件只管框架图。数据图规范见 `可视化规范.md`。

## 一、图类型清单与文件命名

| 图类型 | 文件名 | 适用场景 | 放置位置 |
|---|---|---|---|
| **技术路线图**（必备） | `fig_roadmap` | 整体解题路线、章节逻辑、方法串联 | 问题重述 / 绪论 |
| 子问题求解流程图 | `fig_flow_q1` / `fig_flow_q2` / `fig_flow_q3` | 单子问题：输入→判断→算法→输出 | 对应问题章节 |
| 数据处理流程图 | `fig_pipeline` | 数据清洗、特征构造、建模输入 | 数据预处理节 |
| 模型结构图 | `fig_model` | 模块关系、变量关系、模型层次 | 模型建立节 |
| 指标体系图 | `fig_index_system` | 目标层→准则层→指标层 | 综合评价类题目 |
| 决策树/规则图 | `fig_decision_tree` | 分类规则、方案选择、策略分支 | 对应模型节 |

**竞赛论文通常至少需要一张 `fig_roadmap` 技术路线图。**

## 二、五个内置模板（`utils/diagram.py`）

| 函数 | 版式 | 用途 |
|---|---|---|
| `diagram_roadmap(content)` | 竖版五带（954×1296） | 技术路线图：提出问题→数据指标→方法机制→结果对比→评价推广 |
| `diagram_framework(content)` | 三栏（阶段链/内容块/方法清单） | 研究内容全景 / 模型结构图 |
| `diagram_stageflow(content)` | 三栏阶段流（实色标题条） | 执行流程 / 阶段推进 |
| `diagram_taskflow(content)` | 横版任务流水线（16:9） | 课题拆解「任务一…任务四」 |
| `diagram_problem_flow(content)` | 总分布局（顶层→并行→收拢+反馈） | 论文第二章问题分析图 |

### content 契约

```python
# roadmap：5 个带，每带 1~4 项
{"title": "技术路线",
 "bands": [{"head": "提出问题", "items": ["...", "...", "..."]}, ...]}  # 恰好 5 个

# framework：2~4 个阶段
{"title": "研究框架",
 "stages": [{"head": "阶段", "content": ["内容1", "内容2"], "methods": ["方法1"]}, ...]}

# stageflow：恰好 3 个阶段
{"title": "执行流程",
 "stages": [{"head": "阶段一", "steps": ["步骤1", "步骤2", "步骤3"]}, ...]}

# taskflow：2~4 个任务
{"title": "课题拆解",
 "tasks": [{"head": "任务一", "steps": ["步骤1", "步骤2"]}, ...]}

# problem_flow：总问题 + 2~4 分支 + 收拢
{"title": "问题分析", "root": "总问题",
 "branches": ["问题一", "问题二", "问题三"], "bottom": "综合方案",
 "feedback": "反馈修正"}   # feedback 可选
```

**渲染**：`python references/roles/编程手/scripts/render_template.py diagram_roadmap`（或 `--list` 查看全部 26 个模板），产出 PNG(300DPI)+SVG+PDF 三格式。

## 三、语义约定（先想清楚再画）

- **并列**：同一层级的盒子表示「同一抽象层次上的并列项」，宽度/字号/配色一致。
- **汇流**：多根箭头指向同一盒子，表示「多个前置条件汇聚成一个结果」。
- **可对比**：技术路线图里「数据与指标」和「结果对比」两带必须能对应上（前面建了什么指标，后面就要验证什么指标）。
- **每根箭头都有含义**：谁到谁、单向还是双向、扇入还是扇出；说不出含义的箭头**不要画**。

## 四、字数预算与中文断行

- 字宽估算：**全角字符 ≈ 字号**，半角字符 ≈ 字号 / 2（`text_width` 已内置）。
- 行高 ≈ 字号 + 3px。盒子内文字超宽时 `diagram.py` 会**直接抛错**（报出槽位与可用宽度），不要默默溢出。
- 节点文字**短**，必要时手动断行（`"第一行\n第二行"`），不堆长句。
- 竖排中文逐字堆叠，**不要用 rotation 旋转整段中文**。
- 图内不写大段解释，解释留给论文正文；图题（caption）在图**下**。

## 五、连接器 / 箭头规范

- 箭头端点离盒边约 1px，不压进盒子。
- **一分多 / 多合一**：画成「竖线 + 横母线 + 分支」，不画 N 条独立斜线（避免交叉）。
- 正向推进用实线箭头，**反馈/修正用虚线**（暖色，区别于正向）。
- 同类节点的边框、填充、字号、圆角保持一致。

## 六、A / B / C 题框架图侧重

| 题型 | 优先框架图 |
|---|---|
| **A 题（机理/物理）** | 受力/几何/机理示意图、变量关系图、网格/时间步示意 |
| **B 题（优化/决策）** | 算法流程图、状态转换图、可行域/约束示意、Pareto 前沿 |
| **C 题（数据/统计）** | 数据总览图、指标体系图、聚类/关联分析流程 |

## 七、自检清单（交付前逐项过）

- [ ] **不为装饰而画**：每张图对应 `题目分析报告` 里的真实方法，说不清就删。
- [ ] 至少一张 `fig_roadmap` 技术路线图，且在绪论/问题重述中。
- [ ] 文件命名与图意一致（`fig_roadmap` / `fig_flow_q1` / `fig_pipeline` / `fig_model`…）。
- [ ] 文字语言与论文语言一致（国赛中文、美赛英文），不中英混排。
- [ ] 九区盘点：① 文字溢出/压线 ② 箭头方向与语义 ③ 同族元素对齐同宽 ④ 数值/术语没有抄错。
- [ ] 箭头不交叉、不穿过核心节点。
- [ ] 与数据图不重复（框架图里不塞折线/柱状图）。
- [ ] 渲染无报错、三格式（PNG+SVG+PDF）齐全，`figure_audit.py` 通过。
